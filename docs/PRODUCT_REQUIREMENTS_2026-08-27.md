## 2. 확정 정책

### 2.1 기존 데이터와 호환성

- 기존 개발 데이터와 기존 투표 데이터는 보존 대상이 아니다.
- 권한 비트, 설문 유형, 시드와 개발 마이그레이션은 새 모델에 맞춰 정리할 수 있다.
- 폐기 기능을 위한 호환 분기와 사용되지 않는 UI·API·시드는 제거한다.
- 운영 데이터가 실제 배포 환경에 존재하는 시점부터는 파괴적 변경 전 백업과 마이그레이션 검증을 별도로 수행한다.

### 2.2 콘텐츠 이미지

- 홈 히어로는 단일 이미지를 유지한다. 관리자는 기존 이미지를 교체한다.
- 조직도는 국문 이미지와 영문 이미지를 각각 등록할 수 있다.
- 이미지 편집은 출력 비율을 고정하고 확대, 이동, 초점 위치 조정 중심으로 제공한다.
- 자유 비율 자르기는 공개 페이지 레이아웃을 깨뜨릴 수 있으므로 제공하지 않는다.

### 2.3 권한과 제재

- 권한은 허용 권한을 더하는 additive RBAC로 유지한다.
- 기본 권한을 상쇄하는 deny 역할 또는 빈 블랙리스트 역할은 만들지 않는다.
- 로그인 차단, 게시 활동 정지 등 제재는 역할과 별도 데이터로 관리한다.
- 최고 관리자 권한은 운영 편의를 위한 묶음 권한이 아니라 비상용 전체 권한으로 취급한다.

### 2.4 게시글 관리

- 작성자는 자기 게시글과 댓글을 수정할 수 있다.
- 게시글 관리자는 타인의 게시글과 댓글을 수정할 수 없다.
- 게시글 관리자는 사유와 함께 콘텐츠를 숨기고 복원할 수 있다.
- 숨김 콘텐츠와 원문은 증거·감사 목적으로 보존한다.
- 영구 삭제는 일반 운영 UI에서 제공하지 않는다.
- 익명 작성자 신원 확인은 권한이 있는 관리자에게만 별도 액션으로 제공하고 조회 기록을 운영 로그에 남긴다.

### 2.5 설문과 투표

- 설문 유형은 `일반 설문`과 `행사 신청`으로 단순화한다.
- 투표는 설문과 분리해야 하며 현 단계에서는 기능, 권한, 생성 UI와 공개 노출에서 제거한다.
- 게시글과 설문은 1:1 관계로 제한한다.
- 일반 설문과 행사 신청은 응답이 존재해도 문항을 수정할 수 있다. 기존 응답 원문은 보존하며, 삭제된 문항은 이후 제출에서만 제외한다.
- Google Sheets는 지정 Drive 폴더에 설문별 응답 시트를 생성하고 연결 후 제출 데이터를 지속 반영한다.

### 2.6 내부 연락망과 공개 구성원

- 집행위원회 연락망은 내부 운영 데이터로 취급한다.
- 연락망 등록만으로 공개 학생회 구성원에 노출되지 않는다.
- 공개 구성원이 필요하면 별도 공개 프로필 데이터 또는 명시적인 공개 설정을 사용한다.

## 4. 사이트 설정

### 4.1 이미지 등록과 편집

- 히어로, 로고, 조직도 업로드에 공통 이미지 선택·크롭 컴포넌트를 사용한다.
- 슬롯별 고정 비율 안에서 확대, 축소, 이동과 초점 위치 조정을 제공한다.
- 저장 전 결과 미리보기를 제공한다.
- 조직도는 `한국어`와 `English` 이미지 슬롯을 모두 제공한다.
- 히어로는 단일 슬롯만 제공하고 기존 이미지를 교체한다.

### 4.2 제거할 필드와 기능

- 단일 이미지 슬롯에 예약, 보관, 노출 시작·종료, 노출 순서와 콘텐츠 유형을 요구하지 않는다.
- 사용되지 않는 과거 CMS 필드와 분기를 정리한다.

## 5. 일정 관리

### 5.1 기간 검색

- 제목 검색과 함께 시작일·종료일 범위 필터를 제공한다.
- 선택 범위와 하루라도 겹치는 일정을 반환한다.
- 겹침 조건은 `event.startAt <= rangeEnd AND event.endAt >= rangeStart`이다.
- 초기화와 `이번 달` 빠른 선택을 제공한다.
- Google 동기화와 KAIST 동기화 이후에도 같은 필터 상태를 유지한다.

### 5.2 기존 관리 정책 유지

- 행을 선택하면 상세 드로어를 연다.
- 숨김 일정은 목록에서 낮은 opacity로 표시한다.
- 기술 JSON과 드로어 내부의 불필요한 중첩 스크롤바를 노출하지 않는다.
- 공휴일은 임의 문자열 추론이 아니라 Google Calendar의 Korean holiday 소스를 기준으로 분류한다.

## 6. 사용자 관리

### 6.1 계정 비활성화

- 비활성화 시 사유를 필수 입력한다.
- 선택적으로 사용자에게 안내 메일을 발송할 수 있다.
- 메일 실패가 계정 비활성화 트랜잭션을 되돌리지는 않는다.
- 비활성 사용자가 로그인하면 일반 로그인 실패가 아닌 전용 안내를 표시한다.
- 안내에는 비활성화 사실과 사이트의 채널톡 문의 방법을 포함한다.
- 비활성화, 해제, 사유 변경을 운영 로그에 남긴다.

### 6.2 전공과 필터

- 사용자 목록과 상세에서 주전공, 복수전공, 부전공을 구분해 표시한다.
- 전공 데이터의 권위 원천은 SSO 동기화 값으로 두고, 누락 시 관리자 가져오기·정정 경로를 제공한다.
- 다음 필터를 제공한다.
  - 주전공
  - 복수전공
  - 부전공
  - 학적 상태
  - 과비 납부 상태
- 필터 결과의 전체 인원 수를 표시한다.
- 옵션별 인원 수가 필요할 경우 현재 다른 필터를 적용한 상태의 facet count로 계산한다.

### 7.2 기본 사용자 권한

- 로그인 사용자는 건의사항을 작성할 수 있다.
- 로그인 사용자는 연구실 게시판을 작성할 수 있다.
- 연구실 작성 권한은 모든 인증 사용자에게 적용되는 기본 권한으로 계산하며, 별도 역할이 없어도 동작한다.
- HoC와 홍보는 공지·행사 작성 권한에 포함한다.
- 행사 등록도 공지·행사 작성 권한으로 허용한다.

### 7.3 관리자 셸과 메뉴

- 위 관리 권한 중 하나라도 보유하면 관리자 셸에 진입할 수 있어야 한다.
- 각 메뉴는 해당 권한만 검사한다.
- 권한·역할 관리 권한을 가져도 다른 관리자 페이지 권한이 자동으로 생기지 않는다.
- 폐지된 `운영 도구 관리` 권한, 챗봇과 POM 채점기 관련 메뉴·라우트·시드를 제거한다.
- `학생회비 관리`, `과비 납부 관리` 등 혼재된 이름은 `과비 관리`로 통일한다.

### 7.4 역할 구성원 추가

- 이름, 학번, 이메일 검색을 유지한다.
- 전공, 학적, 과비 납부 상태 필터를 추가한다.
- 선택 결과와 총 인원 수를 명확히 표시한다.

### 7.5 제재 모델

- `ACCOUNT_DISABLED`: 로그인 차단
- `POSTING_SUSPENDED`: 게시글·댓글 작성 차단
- 각 제재는 사유, 처리자, 시작일, 만료일과 해제 이력을 가진다.
- 빈 역할을 deny 용도로 사용하지 않는다.

## 8. 게시판과 댓글

### 8.1 공식 답변

- 건의사항의 일반 댓글 허용이 꺼져 있어도 공식 답변은 작성할 수 있다.
- 공식 답변 권한자는 비밀 건의사항을 읽을 수 있다.
- 공개 화면의 작성자명은 `전산학부 집행위원회`로 표시한다.
- 실제 작성자 ID는 보존하고 운영 로그에서 확인할 수 있어야 한다.

### 8.2 비밀글

- 소유자가 자기 비밀글 알림을 통해 정상 접근할 수 있어야 한다.
- 권한 없는 사용자가 접근하면 `존재하지 않는 게시글입니다`가 아니라 `비밀글입니다` 상태를 표시한다.
- 존재 여부 노출에 관한 보안 정책은 목록에서 이미 비밀글 존재가 노출되는 범위와 일치시킨다.

### 8.3 관리와 보존

- 관리자 타인 글·댓글 수정 권한을 제거한다.
- 숨김 시 사유를 필수로 입력하고 작성자에게 필요한 경우 상태를 안내한다.
- 관리자 화면에서 숨김 콘텐츠를 필터링하고 복원할 수 있다.
- 익명 작성자 확인 액션은 게시글 관리자에게만 제공하고 감사 로그를 남긴다.

### 8.4 임시저장과 상세 탐색

- 게시글 작성·수정 화면에 서버 임시저장, 복구와 삭제 UI를 다시 노출한다.
- 상세 화면에 같은 게시판의 이전글·다음글을 제공한다.
- 고정 공지는 배경 강조와 핀 아이콘을 함께 사용한다.

### 8.5 답글

- 댓글과 답글 작성자는 자기 내용을 수정할 수 있다.
- 답글이 많은 경우 답글 자체를 따로 잘게 페이징하지 않는다.
- 최상위 댓글 스레드를 20개 단위로 페이지 또는 커서 페이징하고 각 스레드의 답글을 함께 표시한다.

### 8.6 조회수

- 로그인 사용자의 조회수는 계정당 한 번만 집계한다.
- 새로고침으로 조회수가 반복 증가하지 않는다.
- 이 값은 페이지 열람 횟수가 아니라 고유 로그인 열람자 수에 가까운 지표임을 운영 문서에 명시한다.

## 9. 게시판 설정

### 9.1 생성 안정성

- 새 게시판 모달에서 입력을 시작해도 닫히거나 상태가 초기화되지 않아야 한다.
- 클라이언트 오류, API 오류와 validation 오류를 분리해 표시한다.

### 9.2 사용되지 않는 설명

- 공개 화면에서 사용하지 않는 게시판 설명 입력은 관리자 UI에서 제거한다.
- DB 필드는 다른 사용처가 없으면 스키마 정리 시 제거한다.

### 9.3 기능 토글

- 댓글 비활성: 상세·작성 화면에서 댓글 UI를 숨기고 API도 거부한다.
- 비밀글 비활성: 작성 화면에서 비밀글 옵션을 숨기고 API도 거부한다.
- 추천·스크랩 비활성: 추천과 스크랩 UI를 모두 숨기고 두 API를 모두 거부한다.
- 실패 토스트로 비활성 기능을 설명하는 대신 사용할 수 없는 UI를 렌더링하지 않는다.

### 9.4 읽기·쓰기 범위

- 읽기 범위는 `공개`와 `로그인 사용자만`을 제공한다.
- 쓰기 범위는 로그인 사용자 전체 또는 지정 작성 권한으로 설정한다.
- 특정 개인 계정 목록은 게시판에 직접 저장하지 않고 역할과 권한으로 관리한다.

- 여러 FAQ를 동시에 열 수 있는 접근 가능한 아코디언을 사용한다.

## 11. 설문조사 관리

### 11.1 유형 정리

- 신규 유형은 `SURVEY`와 `APPLICATION`만 사용한다.
- 기존 `GENERAL`, `EVENT`, `VOTE` 분기와 투표 UI·시드·권한을 제거한다.
- 공개 라벨은 `일반 설문`, `행사 신청`으로 통일한다.

### 11.2 설문 참여 자격

관리자는 설문별로 다음 조건을 설정할 수 있다.

- 로그인 사용자 전체
- 전산학부 소속자만
  - 주전공
  - 복수전공
  - 부전공
- 학적 제한
  - 제한 없음
  - 재학생만
  - 재학생·휴학생
- 과비 납부자만

기본 권장값은 다음과 같다.

- 전산학부 주전공·복수전공·부전공 허용
- 재학생·휴학생 허용
- 과비 제한 없음

전공 선택 항목끼리는 OR로 계산하고, 전공·학적·과비 조건끼리는 AND로 계산한다.

예시:

> `(전산학부 주전공 OR 복수전공) AND (재학생 OR 휴학생) AND 과비 납부 완료`

서버는 응답 생성과 수정 시 모두 자격을 검증한다. 전공 데이터가 비어 있으면 전공 제한을 충족하지 않은 것으로 처리한다. 비로그인 참여와 전공·학적·과비 제한은 함께 사용할 수 없다.

참여 불가 오류는 원인을 구분한다.

- 로그인이 필요합니다.
- 이 설문은 전산학부 주전공·복수전공·부전공자만 참여할 수 있습니다.
- 이 설문은 재학생·휴학생만 참여할 수 있습니다.
- 이 설문은 과비 납부자만 참여할 수 있습니다.

전공명 문자열 비교는 단일 공통 판별 함수에서 처리한다. SSO 입력 단계에서 전산학부의 국문·영문 별칭을 정규화하고 각 서비스가 임의 문자열을 직접 비교하지 않는다.

권장 계약 예시:

```ts
type SocAffiliation = "PRIMARY" | "DOUBLE" | "MINOR";
type AcademicEligibility = "ANY" | "ENROLLED_ONLY" | "ENROLLED_OR_LEAVE";

interface SurveyEligibility {
  socAffiliations: SocAffiliation[];
  academicStatus: AcademicEligibility;
  feePayersOnly: boolean;
}
```

### 11.3 비로그인 참여

- 설문별 `로그인 없이 참여 허용` 설정을 제공한다.
- 전공, 학적 또는 과비 조건을 하나라도 사용하면 이 설정을 비활성화한다.
- 비로그인 설문은 계정 기반 중복 방지를 보장하지 못한다는 안내를 관리자에게 표시한다.
- 공개 제출 API에는 요청 빈도 제한과 자동화 방어를 적용한다.

### 11.4 편집 정책

투표 기능은 별도로 분리하고 현 단계에서 제거한다. 남은 일반 설문과 행사 신청은 응답 존재 여부와 무관하게 제목, 설명, 문항, 선택지, 분기, 일정과 공개 설정을 수정할 수 있다. 기존 응답 원문은 그대로 보존하며 삭제된 문항은 이후 제출에서만 제외한다. 관리 화면은 기존 응답과 현재 문항 정의가 다를 수 있음을 표시하고, 결과 집계는 현재 남아 있는 문항을 기준으로 계산한다.

### 11.5 이미지와 파일 문항

- 설문 설명과 문항 설명의 공통 리치 텍스트 에디터에 이미지 삽입을 제공한다.
- 선택지마다 이미지 한 장을 선택적으로 첨부할 수 있다.
- 지원 이미지 형식은 JPG, PNG, WebP로 제한한다.
- 파일 업로드 문항은 최대 파일 수, 파일당 최대 크기와 MIME 허용 목록을 설정할 수 있다.
- 관리자 응답 상세에서 파일명, 형식, 용량과 다운로드를 제공한다.
- 파일 다운로드는 설문 관리 권한을 검사하고 운영 로그에 남긴다.

### 11.6 게시글 연결

- 연결 게시글 선택기는 제목·내용 검색을 지원한다.
- `연결 없음` 저장 시 명시적으로 `null`을 전송한다.
- 한 게시글에는 하나의 설문만 연결할 수 있다.
- 새 연결을 저장할 때 기존 설문 연결을 한 트랜잭션 안에서 해제한다.
- DB에 `connected_article_id` 유니크 제약을 둔다.
- 연결 변경으로 게시글 자체를 생성하거나 복제하지 않는다.

### 11.7 목록과 미리보기

- 설문 목록의 각 행에 `응답`과 `결과` 바로가기를 항상 노출한다.
- 응답이 없으면 `0건` 상태로 표시하되 메뉴 안에 숨기지 않는다.
- 수정, 복제, 보관과 삭제만 더보기 메뉴에 둔다.
- 관리자 미리보기에서는 응답 제출 API를 호출할 수 없다.
- 공개 설문 목록은 진행 중인 모든 설문을 표시하고 데이터가 늘어나면 공통 페이지네이션을 적용한다.

### 11.8 응답자 상세

- 로그인 응답자의 이름을 선택하면 공통 사용자 상세 드로어를 연다.
- 학번, 이메일, 주전공, 복수전공, 부전공, 학적과 과비 상태를 표시한다.
- 비로그인 응답은 사용자 상세 링크를 제공하지 않는다.

### 11.9 Google Sheets 연결

- 설문 결과 연동은 `kaist.helloworld@gmail.com` 사용자 OAuth를 사용한다. 캘린더 동기화용 서비스 계정과 분리한다.
- OAuth 범위는 `drive.file`만 요청한다. 이 범위로 앱이 만든 Sheets 파일을 생성·수정할 수 있으며 Gmail 읽기·쓰기·발송 권한은 요청하지 않는다.
- 앱이 사용자 내 드라이브에 `KAIST SOC 설문 결과` 폴더를 한 번 생성해 재사용한다. 운영자가 이 폴더를 다른 폴더 아래로 이동해도 앱이 만든 파일에 대한 접근은 유지된다.
- OAuth client와 refresh token은 각각 별도 비밀 파일로 관리하고 저장소에 커밋하지 않는다.

```env
GOOGLE_OAUTH_CLIENT_KEY_FILE=/run/secrets/google-oauth-client.json
GOOGLE_OAUTH_TOKEN_FILE=/run/secrets/google-oauth-token.json
GOOGLE_SURVEY_RESULTS_FOLDER_NAME=KAIST SOC 설문 결과
```

- 관리자가 설문에서 `Google Sheets 연결`을 한 번 실행하면 앱 전용 결과 폴더에 스프레드시트를 생성한다.
- 파일 이름은 `[설문 제목] 응답 · {surveyId}` 형식으로 하여 동명 설문 충돌을 막는다.
- 설문에는 `spreadsheetId`, `spreadsheetUrl`, 연결 시각과 마지막 동기화 상태를 저장한다.
- 첫 행에는 제출 시각, 응답 ID, 응답자 기본 정보와 문항 제목을 기록한다.
- 제출 완료 응답만 반영하고 임시 응답은 반영하지 않는다.
- 응답 생성·수정 후 response ID를 기준으로 시트 전체를 다시 정규화해 중복 행과 오래된 값을 남기지 않는다. 학생회 규모의 응답 수에서는 이 방식이 단순하고 안전하다.
- 연결 작업과 응답 동기화는 실패 시 응답 제출 자체를 실패시키지 않는다.
- 실패 상태와 재시도 액션을 관리자 화면에 표시한다.
- 연결 해제는 시트 파일을 삭제하지 않고 이후 동기화만 중단한다.
- 이미 연결된 설문에서 다시 연결을 눌러 중복 시트를 생성하지 않는다.

## 12. 과비 관리

- 화면과 권한 명칭을 `과비 관리`로 통일한다.
- 상단은 검색, 상태·연도·전공 필터와 핵심 액션을 한 줄 툴바로 구성한다.
- 복수 선택은 체크박스, Shift+클릭 구간 선택과 `현재 필터 결과 전체 선택`을 지원한다.
- 마우스 자유 드래그 선택은 스크롤·텍스트 선택 충돌 때문에 제공하지 않는다.
- 기간별 조회와 납부 추이는 통계 화면에서 제공하고 실무 테이블과 분리한다.
- 실제 총무 사용자 테스트를 별도 수용 단계로 수행한다.

## 13. 이메일 일괄 발송

### 13.1 실제 발송

- 로컬과 테스트 환경은 `EMAIL_DRY_RUN=true`를 유지한다.
- 운영 서버에는 Dooray SMTP 자격 증명과 공식 발신 주소를 환경 변수로 설정한다.
- 운영 smoke test 후에만 `EMAIL_DRY_RUN=false`로 전환한다.
- 비밀값은 문서, Git 또는 클라이언트 코드에 기록하지 않는다.

### 13.2 정보 구조

- 한 관리 화면 안에서 `작성`, `템플릿`, `발송 내역` 탭으로 분리한다.
- 템플릿 생성·수정·삭제를 작성 폼 내부에서 수행하지 않는다.
- 학번 범위, 입학 연도, 전공, 학적과 과비 상태 필터를 제공한다.
- 작성 단계에서도 수신자 수와 표본을 확인하고 전체 명단은 드로어에서 검토할 수 있다.
- 최종 검토 단계에서 실제 수신자 명단과 제외 사유를 표시한다.

## 14. 집행위원회 연락망

- 연락망은 내부 관리자와 XLSX 내보내기에만 사용한다.
- 공개 학생회 구성원으로 자동 노출하지 않는다.
- XLSX는 실제 Office Excel에서 열리는 유효한 OOXML 파일로 생성하고 다운로드 테스트를 둔다.
- 내보내기·불러오기 중 버튼 문구와 폭을 바꾸지 않는다.
- 채널톡 기본 런처는 건드리지 않고 모달 하단에 launcher safe area를 확보한다.

## 15. 운영 로그

- 시스템 키 대신 사람이 이해할 수 있는 작업명, 대상과 결과를 표시한다.
- 권한 변경, 익명 작성자 신원 확인, 콘텐츠 숨김·복원, 계정 제재, 파일 다운로드와 Google Sheets 연결을 기록한다.
- 현 단계에서는 별도 기능 확장보다 실제 운영 피드백과 로그 누락 검증을 우선한다.

## 16. 홈 화면

### 16.1 행사 캐러셀

- 현재 진행 중인 행사와 가까운 예정 행사를 표시한다.
- 기본 정렬은 `고정 행사 → 진행 중이며 마감 임박 → 시작 예정이며 시작 임박`이다.
- 관리자가 홈 노출 여부와 고정 순서를 행사 자체에서 설정할 수 있게 한다.
- 별도 CMS에 행사 데이터를 복제하지 않는다.
- 데스크톱은 3장을 유지하고 한 번에 한 카드씩 이동하는 sliding window를 사용한다.
- 마지막 구간에서도 카드 폭이 변하지 않고, 이전 카드와 겹쳐 3장 뷰를 유지한다.
- 처음과 마지막에서 각각 불가능한 이전·다음 버튼을 숨기고 무한 루프는 사용하지 않는다.

### 16.2 게시판 위젯

- 게시글 수에 따라 행 높이를 늘리거나 카드 높이를 비례 분배하지 않는다.
- 게시글 한 건은 일반 행 높이로 표시하고 아래 공간은 자연스럽게 남긴다.
- 빈 더미 행을 만들지 않는다.

### 16.3 검색과 알림

- 통합 검색 기본값은 제목과 내용을 함께 검색한다.
- 제목·내용 선택은 결과 페이지의 고급 필터로만 제공하고 헤더 검색을 복잡하게 만들지 않는다.
- 알림 팝업에는 읽지 않은 최근 알림을 표시한다.
- `전체 알림` 페이지에서는 읽은 알림을 포함한 이력을 공통 페이지네이션으로 제공한다.
- 읽은 알림은 팝업에서 제거하지만 전체 내역에는 유지한다.

### 16.4 푸터

- 작은 화면과 확대 상태에서도 왼쪽 내용이 잘리지 않아야 한다.
- 공식 이메일을 표시한다. 현재 값 `contact@cs.kaist.ac.kr`이 실제 공식 주소인지 배포 전에 확인한다.

## 17. 공개 행사·일정·설문

- `행사·일정` 화면에는 행사와 캘린더만 둔다.
- 설문은 별도 공개 목록으로 분리한다.
- 투표 메뉴와 콘텐츠는 제거한다.
- 카드·목록 수가 페이지 기준을 초과하면 공통 페이지네이션을 사용한다.
- 설문 참여 불가 시 로그인, 전공, 학적과 과비 조건 중 충족하지 못한 이유를 정확히 표시한다.

## 18. 학생회 소개와 공약

- 소개 페이지는 단일 스크롤 구조와 섹션 딥링크를 유지한다.
- 탭 선택 시 브라우저 히스토리를 반복 추가하지 않고 해당 섹션으로 스크롤한다.
- 로드맵 바로가기와 사용되지 않는 별도 구성원 페이지를 제거한다.
- 공개 구성원은 내부 연락망과 분리한다.
- 공약은 닫힌 상태에서 공약명과 진행도만 표시한다.
- 선택 시 상세 설명이 열리는 FAQ형 아코디언으로 변경한다.

## 19. 확인·재현이 필요한 결함 목록

다음 항목은 기능 요구사항과 별도로 재현 테스트와 원인 기록이 필요하다.

- 게시판 추가 모달 입력 중 닫힘 또는 초기화
- 추천 비활성 게시판에서 스크랩 가능
- 내 비밀글 댓글 알림의 잘못된 접근 거부
- 설문 연결 변경 중 게시글 또는 목록 행 중복
- 설문 연결 해제 미반영
- 공개 설문 목록 일부 누락
- 공개 설문 제출 실패
- 홈 행사 마지막 구간의 카드 폭·개수 변화
- 홈 게시글 한 건 레이아웃
- 특정 viewport의 푸터 왼쪽 잘림
- 채널톡과 연락망 모달 하단 액션 겹침
- 관리자 단일 권한 사용자의 관리자 셸 미노출

각 결함에는 재현 조건, 기대 결과, 실제 결과, 관련 API 응답과 회귀 테스트를 남긴다.

## 20. 완료 정의

- 권한별 API 테스트와 관리자 route 접근 테스트가 통과한다.
- 설문 참여 자격은 UI 표시와 서버 판정이 일치한다.
- 설문 연결 1:1 제약과 연결 해제가 DB 수준에서 보장된다.
- Google Sheets 연결, 신규 응답 추가, 응답 수정, 실패 재시도와 중복 연결 방지가 검증된다.
- 파일 문항의 업로드, 제출, 관리자 다운로드와 권한 거부가 검증된다.
- 비활성 계정, 비밀글, 공식 답변과 숨김 콘텐츠의 안내 문구가 원인별로 구분된다.
- 게시판 기능 토글이 공개 UI와 API 양쪽에 동일하게 적용된다.
- XLSX 내보내기 파일을 Microsoft Excel로 열 수 있다.
- 기존 투표·운영 도구 코드와 사용되지 않는 권한·시드가 제거된다.

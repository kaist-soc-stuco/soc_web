# SOC 기반 개편 결정사항

작성일: 2026-07-15

이 문서는 대규모 기능 추가와 화면 개편 전에 적용할 제품·운영 기준의 기준점이다. 구현 중 충돌이 생기면 아래 결정사항을 우선하고, 보안이나 데이터 무결성을 약화시키는 예외는 별도 검토 없이 추가하지 않는다.

## 확정된 제품 기준

- 공식 대외 브랜드 표기는 한국어와 영어 모두 `SOC`로 통일한다.
- 공식 Instagram은 `https://www.instagram.com/in.cs.tagram/`만 노출한다. 확인되지 않은 SNS 링크는 표시하지 않는다.
- 현재 데이터는 개발·초기 운영 데이터로 보고 초기화할 수 있다. 마이그레이션은 운영 데이터 보존보다 올바른 스키마와 seed 분리를 우선한다.
- 학생회비는 사용자마다 하나의 납부 상태를 관리자가 수동으로 변경한다. 학기별 거래 원장, 입금 자동 대조, 증빙·환불 기능은 현재 범위에 포함하지 않는다.
- 홈, 소개, 구성원, 배너, 주요 행사 등 운영 콘텐츠를 코드에서 분리하는 CMS가 필요하다.
- 외국인 학생을 위해 공개 사용자 화면은 한국어·영어를 모두 완전하게 지원한다. 단순 번역 토글이 아니라 콘텐츠 누락 상태와 번역 상태도 관리한다.
- 화면 개편 순서는 데스크톱 관리자 업무 화면을 우선하고, 공개 화면은 모바일 사용성을 필수 품질 기준으로 유지한다.

## 별도 답변이 없었던 항목의 기본 정책

- 게시판 접근 범위는 `PUBLIC`, 로그인 구성원용 `MEMBERS`, 운영진용 `STAFF_ONLY`를 서버에서 일관되게 강제한다. 목록, 상세, 검색, 댓글, 일정, 첨부파일에 같은 정책을 적용한다.
- 대량메일은 실제 발송 공급자, 발신 도메인, 수신 거부, 테스트 발송, 승인 절차가 확정되기 전까지 비활성화한다. 로그 출력만 하고 성공으로 처리하지 않는다.
- 설문은 기본적으로 사용자당 한 번 응답한다. 명시적으로 복수 응답을 허용한 설문만 반복 제출할 수 있으며, 정원과 중복 여부는 데이터베이스 트랜잭션에서 보장한다.
- 게시된 설문의 질문과 선택지는 응답 정합성을 깨뜨리지 않도록 버전 또는 스냅샷으로 고정한다.
- 자유서술 응답은 기본 비공개로 취급하며, 공개 결과에는 운영자가 명시적으로 검토·승인한 집계만 노출한다.
- 개인정보 처리방침에는 수집 항목, 목적, 보유 기간, 운영 주체, 문의처, 열람·정정·삭제·동의 철회 절차를 한국어와 영어로 제공한다.
- 사용자는 로그인 후 원래 요청한 경로로 돌아가며, 인증·권한·네트워크 오류와 실제 빈 상태를 서로 다른 화면으로 표시한다.
- 운영 환경에서는 demo seed를 실행하지 않는다. 기준 데이터 seed와 데모 콘텐츠 seed를 분리하고 production guard를 둔다.
- 저장소에 노출됐던 공공데이터포털 휴일 API 키는 폐기·재발급하고 `KOREAN_HOLIDAY_API_KEY` 환경변수로만 주입한다.

## 구현 순서

1. 저장형 XSS, 접근 제어, 첨부파일, 설문 동시성, 가짜 대량메일과 취약 의존성 등 배포 차단 항목
2. 서버 권한 정책, 트랜잭션, 요청·응답 계약, 오류 모델과 API 클라이언트 단일화
3. CMS 콘텐츠 모델과 번역 워크플로, 관리자 데스크톱 정보 구조
4. 홈, 행사·일정, 게시판, 설문·마이페이지, 관리자 화면 순서의 재설계
5. 통합 테스트, 브라우저 E2E, 접근성·시각 회귀, 운영 관측성과 배포 점검

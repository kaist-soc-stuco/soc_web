## 2. 수정 전 실제 문제 재현

`/calendar`, viewport `390×844`에서 다음을 측정했다.

| 항목 | 수정 전 측정값 | 문제 |
| --- | ---: | --- |
| 달력 내부 래퍼 폭 | `560px` | 모바일 화면보다 넓은 고정 폭 |
| 날짜 칸 폭 | `80px` | 390px 화면에서 7열이 화면에 맞지 않음 |
| 달력 내부 위치 | `x=40.8`, right=`600.8` | 카드 밖으로 이어지는 가로 스크롤 영역 |
| `min-w-[560px]` 사용 | 1개 | 계획서가 지적한 원인과 일치 |

페이지 전체 `scrollWidth`만 보면 오버플로가 false였지만, 이는 달력에 `overflow-x-auto`가 걸린 중첩 스크롤이 페이지 폭을 가렸기 때문이다. 사용자는 달력 안에서 가로로 밀어야 했고, 모바일 7열 월간 탐색 목표를 충족하지 못했다.

목록은 `/events`, `390×844`에서 카드 8개가 1열로 표시됐지만 날짜 입력 높이가 `36px`였다. 검색·날짜 필터가 콘텐츠 폭 안에서 재배치될 수 있도록 함께 점검했다.

## 3. 반영한 M08 변경

- 달력 내부의 `560px` 최소 폭과 가로 스크롤을 제거하고 `min-w-0`/`w-full` 7열 그리드로 변경했다.
- 모바일 카드 안쪽 여백을 줄여 날짜 칸을 화면 폭에 맞췄다. 데스크톱에서는 기존 카드/선택일 2열 구조를 유지한다.
- 월 이동 버튼을 44px 기준으로 확대하고 `오늘` 버튼을 추가했다. `오늘`은 현재 월과 오늘 날짜를 함께 선택한다.
- 선택일 상세 패널은 모바일에서 `min-height: 0`으로 자연스럽게 이어지고, 데스크톱에서만 sticky/최소 높이를 유지한다.
- 선택일 일정명·설명·다일 일정 범위는 모바일에서 줄바꿈되며, 상세 카드와 관리자 액션의 터치 영역을 보완했다.
- 행사·설문 카드의 긴 제목/일정/장소를 줄임표로 잘라 정보가 사라지지 않도록 줄바꿈 처리했다.
- 목록 날짜 입력을 `44px`로 확대하고 320px에서 검색창이 항상 다음 줄 전체 폭을 사용하도록 했다.
- 목록/달력 API 오류 상태에 `role=alert`와 `다시 시도` 액션을 추가했다.

## 4. 수정 후 실제 화면 검증

### 달력

| viewport | 페이지 가로 오버플로 | 달력 그리드 | 날짜 칸 | 42일 셀 | 달력 내부 가로 스크롤 |
| ---: | --- | ---: | ---: | ---: | --- |
| `390×844` | 없음 | `301.6px` | `43.1px` | 유지 | 없음 |
| `320×844` | 없음 | `239.2px` | `34.2px` | 유지 | 없음 |

추가 확인:

- 두 viewport 모두 `min-w-[560px]` DOM 사용 수 `0`.
- 390px에서 현재 달력의 이벤트 세그먼트 6개가 유지됐다. 다일 일정 2건이 날짜 칸별로 끊기지 않고 표시됐다.
- 9월 3일을 터치하면 선택일 패널에 `오픈소스 기여 스프린트`, `09.03 (목) 14:00 ～ 09.04 (금) 18:00`, 상세 링크 1개가 표시됐다.
- 상세 링크 터치 시 `/events/15`로 이동했고 실제 행사 상세 화면이 렌더링됐다.
- `오늘` 터치 시 `2026년 9월`, `9월 8일`이 월/선택일로 반영됐다.
- 390px에서 computed `overflow-x: auto|scroll`이면서 실제로 넘치는 달력 요소는 0개였다.

### 행사 목록

- 390px: 날짜 입력 각각 `128.4×44px`, 카드 `335.2px` 1열, 카드 8개, 페이지 가로 오버플로 없음.
- 320px: 날짜 입력은 두 줄로 내려가고 각각 `128.4×44px`, 검색창은 `272.8×44px`로 다음 줄 전체 폭, 카드 `272.8px` 1열, 페이지 가로 오버플로 없음.
- 검색어 `네트워킹` 입력 시 실제 카드 2개만 남고 `전산학부 가을 네트워킹 데이`, `전산인의 밤: 봄학기 네트워킹 데이`가 표시됐다.
- 상태 필터는 실제 DB 수치 `전체 8 / 시작 예정 3 / 진행 중 0 / 마감 5`를 표시했다.

## 6. 결론과 제한 사항

M08의 모바일 목록·달력 목표를 완료했다. 320px/390px에서 페이지 전체 가로 스크롤 없이 7열 달력, 월 이동, 오늘, 선택일 상세, 다일 일정, 상세 이동을 확인했다.

현재 실제 DB 범위에는 한 날짜에 4개를 초과하는 일정이 없어 `+n` overflow 표시 자체는 데이터로 재현하지 못했다. 다만 overflow 계산·숨김 일정 수 표시 코드는 유지했고, 실제 다일 일정과 선택일 목록에서 모든 현재 일정에 접근되는 것을 확인했다.

날짜 입력은 Chromium의 native date control 특성상 자동화 도구의 직접 `fill`이 React change 이벤트를 재현하지 않아, 필드 표시·44px 터치 영역·320px 재배치까지만 브라우저에서 측정했다. 날짜 필터 로직 자체는 M08에서 변경하지 않았으며 기존 코드 경로를 보존했다.
